HydraPing overlay — edge treatment, 1:1

Why it was rough, and what fixes it

  • One path, not two. The seam came from a QSS border-radius fill and a paintEvent stroke being rasterized as two separate rounded rects on nearly the same geometry — their antialiased corners disagree by a fraction of a pixel and fringe. Fill and rim now share a single QPainterPath, so there is nothing to misalign. The preview does the same: one SVG <rect> carrying both fill and stroke.
  • Half-pixel alignment. A 1.1px pen centred on an integer-inset rect straddles a pixel boundary and lands at ~50% coverage on every edge — the classic soft-yet-jagged look. The path is inset by exactly pen_width / 2, putting the centreline on the half-pixel grid.
  • No stacked sub-pixel strokes. The old 0.5px α22 inner ring and the 2× symmetric shadow rings each contributed partial coverage on top of the main stroke. Three overlapping partial-coverage strokes is what actually produced the grain. Now: one rim stroke, one optional inner feather at 0.9px, and the shadow moved off the edge entirely.
  • Device pixel ratio. Qt paints in logical coordinates; on a 125%/150% Windows display a 1.1px pen becomes 1.375/1.65 device px and re-samples badly. Pen width will be quantised against devicePixelRatio so it lands on whole device pixels.
  • Radius continuity. Fill radius 12 and stroke radius 12 on differently-inset rects give non-concentric arcs. The inner feather's radius is now derived (r − inset) so all arcs stay concentric.

Light-theme text — three separate faults

  • Every label is hardcoded white. _create_all_widgets() writes rgba(255,255,255,…) into the message, info, kebab, drink and snooze stylesheets. Light Overlay's text_primary is rgba(33,33,33,250) — near black — so nothing agrees with it. The "Now" column above shows these true colours.
  • _update_theme_colors() never runs at startup. main.py constructs OverlayWindow(theme_name=…) and never calls set_theme(), which is the only path that re-colours anything. Launch with Light Overlay saved and you get white text until you open Settings and re-pick the theme.
  • The info label is re-themed by a dead branch. _update_theme_colors() guards on hasattr(self, '_consumed_label') — that attribute is never assigned anywhere in the file. The widget is _info_label. So even after set_theme(), the ml counter stays white. Drink/snooze are never re-themed at all.

Ring % centring

  • The offset shadow drags it down. The % is drawn twice — black α120 at adjusted(0,1,0,1), then white on top. Measured in offscreen Qt at 35×35: the composite ink sits +0.5px below the ring centre for every value tested. Fix: drop the offset copy.
  • Line-box vs glyph ink. AlignCenter centres the font's ascent+descent box, not the visible digits. Centring on QFontMetricsF.tightBoundingRect() puts the actual ink on the ring's centre.
  • This preview had the same fault, worse. The % was an HTML element centred with place-items:center, inheriting line-height:1.5 → measured 0.75px high. It is now an SVG <text> in the ring's own coordinate system, so no line box is involved.

Design intent (unchanged)

  • Rim, not outline. Alpha varies 105 → 38 → 16 → 30 → 62 along a 135° axis, so the top-left catches light and the long edges nearly vanish.
  • Per-theme edge tint via new edge_hi/edge_lo tokens — white-on-everything is why all eight themes read as one.
