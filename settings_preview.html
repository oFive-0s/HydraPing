HydraPing settings — 525×650, 1:1

The core problem

  • The dialog ignores the theme system entirely. It hardcodes a fixed Google-Material palette — #202124, #E8EAED, #9AA0A6, #3C4043, #8AB4F8 — across roughly 40 inline stylesheets. Pick Wine Red or Forest Green and the overlay changes; this window does not.
  • ThemeManager.get_dialog_stylesheet() already exists and nothing calls it. It is defined once and referenced nowhere else in the project. (The caching bug I fixed in it was therefore in dead code — it only starts mattering once the dialog is actually bound to the theme.)
  • Every input carries a hard 1.5px solid #3C4043 border — thirteen of them stacked down the form. This is the same "outlined" quality you flagged on the overlay, and the fix is the same: recess the field instead of ringing it.

What the proposed pass changes

  • Bound to the theme. Surfaces, text and accent all derive from the active theme, so the dialog matches the overlay it configures. Switch themes in the header to see it move.
  • Grouped, not one flat list. Thirteen equally-weighted rows in a single QFormLayout become five labelled groups. Nothing is added or removed — every control is still here.
  • Borderless fields. Recessed fill plus an inset top highlight; focus is shown with an accent ring rather than a permanent outline.
  • Destructive actions quarantined. "Reset to Defaults", "Reset Water" and "Close HydraPing" currently sit in the same footer row as Save, styled almost identically. They move to a tinted danger zone at the bottom.
  • Sticky footer. Cancel/Save leave the scroll area, so they're reachable without scrolling to the end.
  • Toggles instead of checkboxes for the three on/off settings, and a segmented control for Display Mode — the radio pair reads as a form field for something that's really a two-state choice.

Scrolling — what replaces the Qt default

  • Eased wheel scrolling. QScrollArea jumps ~3 lines per notch instantly, which is what makes a long settings pane feel cheap. An event filter on the viewport intercepts the wheel and drives verticalScrollBar().value through a ~180 ms OutCubic animation, accumulating delta so fast flicks stay responsive.
  • Edge fades instead of a hard cut. A 20px gradient at the top and bottom, each shown only when there is actually content past that edge — so the pane reads as continuing rather than being sliced. Drawn over the viewport in paintEvent.
  • Slim auto-hiding thumb. 4px, sized to the viewport/content ratio, fading in on scroll or hover and out after ~700 ms idle. The current bar is a permanent 5px strip at rgba(95,99,104,140).
  • Sticky group headers so you always know which section you're in. Free in CSS; in Qt this needs either a re-parented header widget above the viewport or a paint-time overlay. This is the one item with real implementation cost — say if you'd rather skip it.
  • Less to scroll. Trimmed the redundant hints and tightened row padding, cutting content height substantially versus the first draft. Exact numbers measured in the browser and reported in chat.
